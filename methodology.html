Methodology

How the benchmark was designed, run, and measured.

Contents

    What this measures

    This benchmark compares fine-tuned open-source language models against commercial frontier APIs on six tasks common in production vertical SaaS products. It measures three things: accuracy on the task, cost to run the task at scale, and where each model fails.

    Every result is reproducible. Training code, evaluation scripts, model weights, and prediction logs are public.

    Tasks

    Each task corresponds to a feature that vertical SaaS teams ship and then struggle to get working on production data. The datasets are public and version-pinned.

    TaskDatasetWhat it testsTest size
    Legal document classificationLEDGAR (LexGLUE)Classifying contract provisions into 100 categories1,000
    Contract clause extractionCUADExtracting clause text from contracts, or correctly reporting its absence4,182
    Customer support routingBANKING77Routing customer messages to 77 fine-grained intent categories3,080
    Financial sentimentFinancialPhraseBankClassifying financial text as positive, negative, or neutral339
    Medical question answeringMedMCQAAnswering 4-option medical multiple-choice questions1,000
    Code generationMBPPWriting Python functions from natural language descriptions, verified by test execution500

    Models

    Three open-source models are fine-tuned with QLoRA. Five frontier APIs are tested zero-shot and with 5-shot prompting. GPT-4.1 mini is also fine-tuned through OpenAI's API for direct comparison against open-source LoRA.

    Open-source (fine-tuned with QLoRA):

    • Qwen3-8B (8B parameters, Apache 2.0)
    • Gemma 3-4B-IT (4B parameters, Gemma Terms of Use)
    • Phi-4-mini-instruct (3.8B parameters, MIT)

    Frontier APIs (prompted):

    • GPT-4.1 at $2.00 / $8.00 per million tokens
    • GPT-4.1 mini at $0.20 / $0.80
    • GPT-4.1 nano at $0.05 / $0.20
    • Claude Sonnet 4.6 at $3.00 / $15.00
    • Gemini 2.5 Flash at $0.15 / $0.60

    API fine-tuned:

    • GPT-4.1 mini via OpenAI SFT at $0.80 per million training tokens

    Each model is tested under conditions that match how teams actually deploy it.

    LoRA (500)Open-sourceQLoRA fine-tuned on 500 training examples

    A data efficiency curve for Qwen3-8B is computed per task at 50, 200, 500, 1,000, 2,000, and 5,000 training examples where data permits.

    Metrics

    Task accuracy. The primary quality metric: weighted F1 for classification tasks, token-level F1 for extraction, accuracy for multiple-choice, pass@1 for code generation.

    Cost per 1,000 correct predictions. The total cost to produce 1,000 correct outputs, combining amortized training cost (spread over 12 months at 10K daily queries) and per-query inference cost. This metric directly answers "is fine-tuning worth the investment?"

    Latency. Time to first token at P50 and P95. Self-hosted models report vLLM serving latency. API models report end-to-end request latency.

    12-month TCO at 10K daily queries. Fully loaded annual cost including compute, API fees, and one-time training.

    Error analysis

    Every prediction is classified into one error category. The rules are deterministic and applied by code, not by judgment.

    Classification tasks use five categories: correct, wrong class, format violation (output doesn't map to a valid label), refusal, and empty output.

    Extraction uses five categories: correct (token F1 above 0.8), partial (F1 between 0.3 and 0.8), missed (failed to find existing content), hallucinated (more than 30% of output tokens absent from source), and format violation.

    Code generation uses five categories: pass (all tests pass), logic error (runs but wrong output), runtime error, syntax error, and incomplete output.

    Training configuration

    All QLoRA fine-tuning uses Unsloth on a single NVIDIA A100 80GB.

    ParameterValue
    Quantization4-bit NF4
    LoRA rank32
    LoRA alpha64
    LoRA dropout0.05
    Target modulesAll linear layers
    Learning rate2e-4 (cosine schedule, 5% warmup)
    OptimizerAdamW 8-bit
    Effective batch size16
    PrecisionBF16
    Seed42
    Epoch schedule10 epochs for N ≤ 200, 5 for 201–1000, 3 for N > 1000
    Checkpoint selectionBest validation loss

    Inference configuration

    Fine-tuned models are served with vLLM. Temperature is 0 (greedy) for all models, including APIs. Maximum output tokens vary by task type: 32 for classification, 512 for extraction, 1,024 for code.
